# Демонстрація: Husky втрачає і відновлює зв’язок

## Запуск після оновлення

У терміналі Linux, з каталогу проєкту:

```bash
git pull --ff-only
bash scripts/run_demo.sh
```

Перший build завантажує ROS/Clearpath/Nav2 та Python-залежності й може тривати
довго. Повторний build використовує Docker cache. Дочекайтеся `Services started`:
це означає, що HTTP-сервіси готові. Сам світ запускається кнопкою в браузері.
`docker compose up -d --no-build` працює лише коли образи вже побудовані.

Відкрийте **http://127.0.0.1:8010/experiments.html**. Вкладка **Місія**:

1. Оберіть **Заїзд за будівлю** та метод **B1**.
2. Натисніть **▶ Запустити місію** один раз.
3. Дочекайтеся підготовки: Gazebo, Clearpath/controllers, Nav2 та перше вимірювання.
4. Спостерігайте проїзд навколо будівлі до заздалегідь перевіреної радіотіні.
5. У радіотіні система підтверджує втрату RSSI. Nav2 повертає робот до цілі,
   обраної за вимірюваннями його антени. Після стабільного відновлення робот зупиняється.

**Tx нерухомий. Rx жорстко закріплений на Husky**, на 0.7 m над base frame.
Координати кузова, орієнтація та обертання коліс надходять із Gazebo/ROS.
Шість visual meshes витягнуті з офіційної Clearpath URDF. Web viewport відображає
стан симулятора. Фізику руху, зіткнення та контролери виконує Gazebo Harmonic.

## Що показує екран

- **LIVE · Gazebo t=…**: поточна симуляція; **ЗАПИС**: окремий replay.
- **Рух → Втрата → Повернення → Відновлено**: фази місії.
- Помаранчевий Tx: база. Зелена антена Rx: на роботі.
- Зелена лінія на підлозі: пройдена траєкторія. Помаранчева: обчислений Nav2 шлях.
- Кольорові точки: реально отримані Sionna RSSI. Графік: згладжений RSSI та поріг.
- **Прогноз карти**: IDW/GPR за доступною історією. **Невизначеність GPR**:
  latent σ; IDW її не оцінює. Ці шари не є еталонною радіокартою.
- **Husky крупно / Весь світ / Зверху** змінюють камеру. ЛКМ — обертання,
  ПКМ — панорама, колесо — масштаб. Прозорі перешкоди допомагають бачити робот.

Метод обирається до запуску. **B0** повертається до останнього відомого доброго
вимірювання; **B1** обирає найкоротший доступний Nav2 шлях до відомої доброї точки;
**IDW** використовує інтерполяцію; **GPR** обирає точки за μ − βσ.
β = 0 оптимістичний щодо невідомих областей; β > 0 враховує невизначеність.

Перед кожним новим RF-полем система незалежно перевіряє ціль радіотіні та чотири
сусідні позиції. Усі мають бути закриті геометрією і принаймні на 3 dB нижче порога.
Ці контрольні покази зберігаються в `shadow_preflight`, **не додаються до історії
контролера**. Сама втрата/відновлення визначається поточними показами на роботі.
Відновлення починається в заданій зоні, а не від випадкового провалу на межі видимості.

## Зупинка та ручне керування

**■ Зупинити рух і експеримент** або **Space** зупиняє місію та утримує робот.
Gazebo залишається прогрітим для наступного запуску. У ручному режимі утримуйте
WASD/стрілки або екранні кнопки; відпускання зупиняє команду. Під час автономного
повернення керування належить Nav2. Закриття вкладки не вимикає сервер.

```bash
docker compose down
```

Ця команда завершує весь стек. Для дебагу:

```bash
docker compose logs --tail 80 radio husky
tail -n 80 .runtime/husky.log
```

## Вікно самого Gazebo

На Linux desktop із DISPLAY і xauth, після запуску місії:

```bash
bash scripts/gazebo_gui.sh
```

Це штатний `gz sim -g`, під’єднаний до того самого запущеного сервера. Для воркера
серії: `bash scripts/gazebo_gui.sh --worker 0`. Потрібні X11/XWayland і локальний
Docker; скрипт передає cookie поточного desktop, не вимикає контроль доступу X11.
Cloud-перевірки виконуються headless: фізичні місії та браузер перевіряються,
інтерактивний desktop GUI у цьому середовищі не перевірений.

## Записи й повтор демонстрації

Вкладка **Записи → Відтворити в 3D** відкриває завершений проїзд.
Повзунок показує стан на обраний момент: вимірювання, карту, ціль, маршрут і режим.
Майбутні вимірювання не домальовуються. Відкриття replay не керує живим роботом.
**Завантажити ZIP** зберігає scene, manifest із версіями/параметрами й timeline JSONL.
Поверніться до **Місія**, щоб бачити живий стан.

Для довільної геометрії перейдіть у **Конструктор світу**. Редагуйте сцени,
матеріали, положення Tx та mount Rx; збережіть JSON. Готові місії мають свої
перевірені маршрути; новий світ потребує перевірки проїзду й окремої цілі радіотіні.
Детальна процедура — [QUALITY.md](QUALITY.md).
